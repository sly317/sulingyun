# 04｜基础数据集构建

## 核心原则：原子化数据

**一列只有一个变量，一格只有一个值。** 一个字段可以是名义数据、序数数据、量化数据、日期、坐标、图像文件引用或文本内容，但不得把多个独立数据塞进同一单元格。

例如：
- 合规：地点名称、纬度、经度分别独立成列。
- 不合规：把“地点名称+纬度+经度”拼成一个字段；把多个标签用逗号塞入一个单元格。
- 合规：姓名、年份、数值分别成列。
- 不合规：在一个单元格中写“张三（2024年，GDP 120）”。

## 数据类型建议
| 类型 | 示例字段 | 存储建议 |
|---|---|---|
| 名义数据 | 名称、类别、地区、材料 | 单一文本值或标准编码 |
| 序数数据 | 等级、阶段、优先级 | 统一编码并附代码表 |
| 量化数据 | 数量、金额、面积、比例 | 数值；单位单独定义或在字段说明中统一 |
| 时间数据 | 日期、年份、时间点 | 统一日期格式 |
| 空间数据 | 纬度、经度、行政区代码 | 坐标分列，注明坐标系 |
| 图像数据 | image_id、文件路径 | 表中保存单一文件标识/路径，图像文件独立存放 |
| 文本数据 | 摘录、描述、标题 | 每格一条独立文本记录；长文本可另存并以ID关联 |

## 表结构规则
- 每行代表一个明确的观察单位/记录。
- 每列代表一个变量，字段名唯一且含义明确。
- 每个单元格仅有一个值；多对多关系使用独立关联表，不用分隔符拼接。
- 缺失值统一表示，并在数据字典中说明；不要把0、未知和不适用混为一谈。
- 记录单位、口径、来源ID、采集时间与清洗规则。
- 原始数据与标准化数据分开保存。

## 建议文件
- raw/：原始数据副本
- processed/：清洗后的原子化数据
- data-dictionary.md：字段定义、类型、单位、取值范围、缺失值规则
- validation-log.md：数据检查与修订记录
- 主数据表.csv：每行一条记录、每列一个变量

## 阶段产出
可供叙事框架组合和视觉编码调用的基础数据集，以及数据字典和质量检查记录。
